### A Preview of Each Pull Request

An application can now have a preview of each pull request, deployed from GitHub Actions to the application's own cluster, with no secret stored anywhere ([harper#3042](https://github.com/HarperFast/harper/issues/3042)). `harper preview setup app=<app>`, run once from a checkout of the repository, calls the new `enable_previews` operation, which creates a user `<app>-ci-preview` whose role can deploy and drop only that application's previews, and two OIDC trust policies for the repository's preview workflow. Setup checks that workflow, or writes a starter one, and sets the `HARPER_PREVIEW_TARGET` repository variable. For each PR, the workflow runs `harper preview deploy`, which deploys the PR's head commit as the isolated application `<app>-pr-<n>` at `<branch slug>.app.<cluster host>`, on its own branch of the databases. Fabric's Colocated and Dedicated clusters serve those hosts with no setup, though a cluster created before preview hosts gains them only as each instance's certificate renews, within about seven weeks. Closing the PR runs `harper preview drop`. The [`HarperFast/deploy-action`](https://github.com/HarperFast/deploy-action) GitHub Action runs the same lifecycle as a workflow step, and comments each preview's URL on its PR. `harper preview teardown`, or `disable_previews`, revokes the identity and drops every preview of the application on every node, and `get_preview_policy` reports how previews are set up. See [Per-PR previews](/learn/developers/deploying-from-ci#per-pr-previews) and [`harper preview`](/reference/v5/cli/commands#harper-preview) ([harper#3505](https://github.com/HarperFast/harper/pull/3505), [harper#3617](https://github.com/HarperFast/harper/pull/3617), [harper#3809](https://github.com/HarperFast/harper/pull/3809), [harper#3807](https://github.com/HarperFast/harper/pull/3807)).

`disable_previews` is a barrier on every node: a preview deploy already going live finishes and is dropped, and one that would go live later is refused with `403`. A node that does not acknowledge it stops `disable_previews` with the identity revoked, and running it again resumes. See [`disable_previews`](/reference/v5/operations-api/operations#disable_previews) ([harper#3812](https://github.com/HarperFast/harper/pull/3812)).
