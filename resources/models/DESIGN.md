# resources/models/ — model facade, backends, decisions

Notes on invariants the models layer relies on that the code cannot state itself. User-facing behavior is documented in HarperFast/documentation.

## Decision outputs are validated at the facade

A `Decision` returned by `models.decide` names a value from the schema's allowed set, and its distribution has exactly one entry per allowed value, with finite probabilities in [0, 1] that sum to one (within 1e-3), sorted descending with ties in schema order unless the backend chose one of the tied values, which then leads. `normalizeDecision` (`decision.ts`) enforces this on every backend output, so no backend's arithmetic is trusted; a violation is a `DecisionContractError`, which `Models.decide` treats like any backend error (recorded against that backend, next candidate tried). A malformed schema or state rejects before routing and writes no analytics row, because nothing was called. Object schemas are marginal-only: `value` is assembled from each field's argmax and may be a combination no single sample produced. Enforced by `unitTests/resources/models/decision.test.js` and `decide.test.js`.

## The generative adapter reports no usage of its own

Every sample the adapter (`generativeDecision.ts`) takes is a `models.generate` call with its own `hdb_model_calls` row and token metrics. The adapter therefore returns no `usage` on its `ModelCallResult`; reporting the sum again would count each sample twice in `SUM(prompt_tokens)` and in `model-*-tokens`, the same double-billing the `toolMode: 'auto'` outer call avoids by writing no row. Samples run under one `AbortController`: the first failure aborts the rest, and the worker pool is awaited to settlement before the error is thrown, so no sample rejects unobserved and the facade never falls back to another candidate while calls are still in flight. Enforced by `unitTests/resources/models/generativeDecision.test.js`.

## Likelihood scoring is a leaf-level hook with voting as the fallback

A generative backend may implement `scoreChoices` (#2838): one finite, unnormalized log-likelihood per choice, in order, for a whole call, or a `ChoiceScoringUnsupportedError` for a call it cannot score. A decline is weaker news than a failure, and the two are kept apart at every layer. The facade's internal `models.scoreChoices` validates the vector's shape before it records a success, so a malformed result is one failed attempt against that backend and the next candidate is tried; when every candidate fails it surfaces the first failure, and the primary's decline only when every candidate declined, so a decline never hides a broken fallback. A declined call is recorded as `scoring_unsupported` with the usage the error carries, because a completion that came back without log-probabilities was still billed: those tokens land on that attempt's failure row and in the token metric while the call-count metric stays a count of successes. They are billed once: no other error's `usage` is read, no other method's failure row carries usage (the `decide` row stays usage-free when a decline propagates under `score`), and the adapter aborts sibling calls with a fresh reason rather than the decline itself, so a call cut short is recorded as `aborted` and not as another copy of the decline. The adapter scores one leaf per call (each property of an object schema separately), normalizes by softmax, and never mixes paths: in `auto` mode a decline, or a `ModelCapabilityError`, discards any leaf already scored and votes the whole decision under the same budget, so a distribution is wholly scored or wholly voted; any other error fails the decision. `auto` asks the router synchronously before deciding, so a generative backend whose capabilities say no costs no attempt, no exception and no analytics row. The OpenAI backend labels the choices `A`..`T` on one line each (a choice's own line breaks are collapsed so it cannot pose as a further option), asks for one token with `top_logprobs: 20`, combines spellings of a label by log-sum-exp, and places a label with no listed spelling only when the mass the list leaves over is smaller than the leading observed label's, so the chosen value can never be an unlisted label whatever its unlisted spellings carried; otherwise the call is declined rather than guessed. An unlisted label then stands at a floor no higher than the smallest listed alternative or the leftover, finite even when the list leaves nothing over, so the order among low-mass labels is an estimate while the leader is not, and a response with no label at all is declined rather than reported as uniform. A malformed alternative is a failure, not a decline. A model that refuses `logprobs`, by a 400 (by `param`, or by a message that names it and says it is unsupported) or by an answer with no log-probability field at all, has scoring switched off until reload and `capabilities()` says so for the configured model, so later decisions vote without an attempt; a completion with no content token or no alternatives, and an answer that is simply not a label, are declined for that call only, and any other HTTP failure stays an error so an outage does not silently turn into voting. Probabilities from scoring are still `calibrated: false`. Enforced by `unitTests/resources/models/generativeDecision.test.js`, `scoreChoices.test.js` and `unitTests/components/openai/index.test.js`.

## Built-ins serve one kind

The provider factories (`ollama`, `openai`, `anthropic`, `bedrock`) treat every non-embedding kind as generative, so a `models.decision` entry naming one would register a backend with no `decide`. `builtinServesKind` (`bootstrap.ts`) refuses that entry at boot and reload, and `wrongKindEntrySchema` (`validation/configValidator.ts`) refuses it at validation, in both directions: `backend: generative` is the only built-in for `decision` and is refused under `embedding` and `generative`. Module backends are exempt because their factory receives `kind`.
